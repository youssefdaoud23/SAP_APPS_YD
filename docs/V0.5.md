# Invarture App Studio v0.5

V0.5 is the first architecture-focused milestone. It keeps the existing plain-Node and browser deployment model while introducing a shared model layer that can later be consumed by a React/TypeScript frontend without changing the application format again.

## What changed

### Shared application model

`lib/platformModel.js` is a browser/Node compatible model library. It centralizes:

- component metadata;
- workspace extension migration;
- nested component traversal;
- environment and connection-alias resolution;
- OData path parsing/building;
- component cloning with fresh IDs;
- typed application variables;
- variable interpolation;
- application validation.

This is the first step away from feature logic being scattered across one large UI file.

### Undo and redo

The browser now keeps up to 40 workspace snapshots per browser session. Studio exposes Undo/Redo buttons and supports:

- Ctrl/Cmd+Z for Undo;
- Ctrl/Cmd+Y or Ctrl/Cmd+Shift+Z for Redo.

Undo/Redo restores the workspace and reloads the editor so the existing v0.4 state model remains consistent.

### Application state

Studio now exposes **State**.

Variables have:

- name;
- type: string, number, boolean, date or JSON;
- scope: application, page or session;
- default value;
- persistence intent.

The State Inspector can apply browser-session test values. Supported text components can interpolate `{{variableName}}` or `{{app.variableName}}`.

### Binding editor

**Binding+** provides one editor for:

- direct server connection or logical connection alias;
- binding mode;
- fallback value;
- EntitySet/path;
- `$select`;
- `$filter`;
- `$orderby`;
- `$expand`;
- `$search`;
- `$top`;
- `$skip`;
- `$count`.

The old Query Builder button is redirected to the enhanced editor.

### Logical environments and aliases

Applications can now bind to logical aliases such as:

`alias:SAP_PRIMARY`

A workspace can map the alias independently in each environment:

- DEV -> `server:sap-dev`
- QAS -> `server:sap-qas`
- PRD -> `server:sap-prd`

The runtime resolves the alias using the active workspace environment. This removes environment-specific server IDs from application definitions.

### Nested layouts

V0.5 introduces a nested `layout` component with one to four slots. Layout slots can contain child components and are preserved as nested application JSON.

The initial slot editor supports adding common child controls. This is intentionally incremental: later releases can move all existing components to the same metadata-driven renderer.

### Reusable fragments

Any selected top-level component can be saved into the workspace Fragment Library. Inserting a fragment deep-clones it and generates new IDs, including nested child IDs.

### Runtime data loader

`runtime-data-v05.js` supersedes the old live-data module and supports:

- direct server connections;
- logical aliases;
- active environment resolution;
- OData V2/V4 response shapes;
- correct app detection when previewing a non-current application;
- configurable live refresh;
- SAP error extraction;
- live indicators.

### Action Designer v0.5

The button Action Designer now supports both direct server connections and aliases. OData writes resolve aliases at runtime and keep all credentials server-side.

Write confirmation and browser demo read-only mode are enforced before mutation requests.

### Developer tools

Studio now exposes **Devtools** with:

- in-memory Network view;
- request method/status/duration;
- safe URL display with secret-like query values redacted;
- captured browser errors;
- application state summary;
- binding inventory.

Secrets are not persisted by Devtools.

### Validation

The v0.5 validator recursively checks nested components and additionally validates:

- invalid or duplicate variables;
- missing environment alias mappings;
- missing binding paths;
- unknown component types;
- OData action connection/path configuration.

## Compatibility

The original `schemaVersion: 2` workspace remains accepted by the v0.4 editor. V0.5 adds `extensionSchemaVersion: 1` and new optional fields rather than breaking the original workspace shape.

This is intentional so an existing workspace does not require a destructive migration.

## Testing

`tests/platform-model.test.js` covers:

- extension migration;
- DEV/QAS alias resolution;
- OData query generation/parsing;
- nested layout cloning;
- application variable interpolation;
- environment-aware validation.

The existing mock SAP CI suite remains in place.

## Suggested test flow

1. Pull `main` and rebuild Docker.
2. Hard refresh the browser.
3. Open an app in Studio.
4. Add a variable from **State**, then use `{{variableName}}` in a text component.
5. Open **Environments**, create `SAP_PRIMARY`, and map DEV/QAS/PRD.
6. Select a Table and use **Binding+** to bind through `alias:SAP_PRIMARY`.
7. Add `$expand`, `$skip` or `$count` and save the binding.
8. Add a 2-column layout, select it and edit its slots.
9. Save a selected component as a Fragment, then insert it again.
10. Make a change and test Undo/Redo.
11. Open Devtools and refresh SAP data to see the request timing.
12. Run Validate while deliberately removing a QAS alias mapping and confirm the error is detected.

## Deployment

Normal self-hosted updates remain:

```bash
git pull
docker compose up -d --build
```
