# V0.6 - shared persistence and authorization foundation

V0.6 moves Invarture App Studio from a primarily browser/file-backed prototype toward a shared multi-user platform foundation.

## What changed

### PostgreSQL is the default Docker workspace store

`docker compose up -d --build` now starts:

- Invarture App Studio on port 8081
- PostgreSQL on the private Compose network

PostgreSQL is not exposed on a host port by default.

The application still supports file storage for direct/local compatibility. Set `WORKSPACE_STORAGE=file` and configure `WORKSPACE_FILE` to use it.

### Shared workspace revisions

The PostgreSQL workspace record stores:

- JSON workspace document
- ETag
- numeric revision
- update timestamp
- updating principal

`GET /api/workspace` returns the current ETag and revision.

`PUT /api/workspace` accepts `If-Match`. A stale ETag receives HTTP 409 instead of silently overwriting a newer shared workspace.

The Server Sync panel displays the active storage backend and revision.

### Platform database schema

V0.6 creates database tables for:

- shared workspace
- permissions
- roles
- role-permission mappings
- users
- user-role mappings
- groups
- group membership
- group-role mappings
- audit events

Built-in roles and permissions are seeded idempotently during database initialization.

### Built-in roles

Current built-in role catalog:

- Platform Admin
- Developer
- Publisher
- Viewer

The role model is server-side and will be reused by OIDC/Entra authentication later.

### Persistent identity mappings

Settings now includes **Shared platform** status and a **Users & groups** administration dialog when PostgreSQL is connected.

Administrators can currently:

- create persistent user identity mappings
- assign/remove built-in roles
- delete identity mappings
- create groups
- assign/remove group roles
- delete groups

The API also supports group membership assignments.

These records are authorization mappings, not a new password database. Authentication remains HTTP Basic or local-development mode in this milestone.

### Audit foundation

PostgreSQL stores append-only platform audit events for important V0.6 mutations, including:

- shared workspace updates
- user creation/deletion
- user-role changes
- group creation/deletion
- group-role changes
- group membership changes

A dedicated audit viewer is planned for a following V0.6 increment.

### Platform status API

`GET /api/platform` reports safe runtime information including:

- running version and commit
- workspace storage mode
- PostgreSQL connectivity
- current workspace revision
- current principal
- effective roles/permissions
- user/group/role counts
- supported V0.6 capabilities

No credentials or database connection strings are returned.

## Docker configuration

The default Compose stack uses PostgreSQL automatically.

For local testing the repository contains a development fallback password in Compose. Before exposing the stack, define a strong `POSTGRES_PASSWORD` in `.env` and configure `APP_STUDIO_USER` / `APP_STUDIO_PASSWORD` until OIDC is implemented.

Example minimum `.env`:

```dotenv
PORT=8081
POSTGRES_PASSWORD=choose-a-strong-local-secret
WORKSPACE_STORAGE=postgres
APP_STUDIO_USER=admin
APP_STUDIO_PASSWORD=choose-a-long-random-secret
SAP_CONNECTIONS_JSON=[]
```

Do not commit `.env`.

## Testing

CI now covers both persistence modes.

File-mode tests verify the existing compatibility path.

PostgreSQL tests verify:

1. database startup
2. schema creation
3. role seeding
4. workspace revision 1 creation
5. ETag-based revision 2 update
6. stale-write HTTP 409 conflict
7. audit records
8. persistent user creation
9. role persistence
10. group creation
11. group membership persistence

## Still transitional

V0.6 does not yet provide production identity authentication.

The current Basic/local principal is mapped to Platform Admin so existing workflows keep functioning while the persistent RBAC model is introduced.

Next work should connect real authenticated identities through OIDC/Microsoft Entra ID, resolve database user/group mappings into effective permissions, and enforce those permissions across connection management, publishing, deployment and SAP write operations.
